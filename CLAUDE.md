# Working style

- Give honest feedback on requests — flag concerns, trade-offs, and better
  alternatives rather than just agreeing. Push back when something seems off.
- Do NOT make any changes until the user approves. For each request, first
  review it and present the expected impact — technical, usability, security,
  reliability, cost, etc. — along with any concerns or alternatives, then WAIT
  for approval. No editing, building, or deploying beforehand.
- Only after the user approves: make the change, build/lint to verify, then
  deploy (commit and push).
- Answer open questions and align on ambiguous decisions before presenting the
  plan, not after.
